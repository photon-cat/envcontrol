CT2 RS-485 Capture Notes
========================

Naming convention: `capture_YYYYMMDD_HHMMSS.log` and `.csv` generated by `buslog.py`.
All capture files now live under `ctinterface/captures/`.
Relay numbering: channels 1–16 = board 1 (address 1), 17–32 = board 2 (address 2), 33–40 = board 3 (address 3, 8 channels).

| Capture | Description | Relay state details |
|---------|-------------|---------------------|
| `capture_20251111_141506` | Partial-on reference | Board 1: relays 1,2,3,4,5,8,16 ON. Board 2: relay 24 ON (channel 8). Board 3: all OFF. |
| `capture_20251111_142403` / `_142502` | Baseline | All relays OFF on every board. |
| `capture_20251111_142641` | End-channel test | Board 1: relay 16 ON. Board 2: relay 32 ON. Board 3: relay 40 (channel 8) ON. |
| `capture_20251111_142947` | Hand override test | HOA switches left in AUTO (controller commands OFF), but relay 1 on each board (1, 17, 33) forced ON with HAND. |
| `capture_20251111_144346` | All switches OFF (no auto) | Every HOA switch physically in OFF, no automatic ON commands active. Results show distinct “all-off” payload signatures. |
| `capture_20251111_144514` | Channels 1/17/33 AUTO, no ON command | All switches OFF except channels 1, 17, 33 in AUTO. Controller still commands OFF, so useful for isolating AUTO-but-idle codes. |
| `capture_20251111_144641` | Manual HAND test | Channels 6, 14, 22, 30, 38 forced to HAND/ON with no auto commands; every other switch in OFF. Demonstrates hand-override pattern on multiple boards. |
| `capture_20251111_144828` | Auto-command ON test | Channels 6, 22, 38 set to AUTO and actively commanded ON; remaining switches OFF. Shows pure AUTO+ON encoding. |
| `capture_20251111_145830` | **Systematic state test (all 40 channels)** | Sequential OFF→AUTO→OFF transitions for channels 1-40, then all set to AUTO. **597 frames** captured. Reveals true frame structure: 19-byte frames (sync + 4 header + 8 payload + 4 trailer). Confirms 5 boards × 8 channels = 40 total. High-confidence state mappings for channels 1-3: OFF=`0x35`, AUTO=`0x65` or `0x99`. |
| `capture_20251111_150227` | **HAND mode systematic test (channels 1-40)** | Sequential toggling of each channel to HAND position and leaving ON. **177 frames** captured. Reveals HAND activation sequence: `0x35 → 0x56 → 0x5A → 0x6A → 0xAA` over ~2 seconds. Confirms HAND fully ON = `0xAA`. **Critical discovery:** Channel-to-byte mapping is NON-sequential (Ch1→byte2, Ch2→byte1, Ch3→byte4, Ch4→byte3 on Board 1). |
| `capture_20251111_161459` | **Controller command vs switch OFF** | Controller commands channel 6 ON, but all switches in OFF position. Relay stays OFF. **20 frames**. Shows controller attempting activation (variant=`0x65`) but channel state remains OFF because physical switch is in OFF position. Demonstrates controller can't override OFF switch position. |
| `capture_20251111_161616` | **Controller command with AUTO switch** | Switch 6 in AUTO position. Controller commands it ON mid-capture. **29 frames**. Shows transition from AUTO-idle to AUTO-ON when controller sends activation command. Channel 6 byte changes from `0x35` to `0x59` showing AUTO+ON state. Confirms controller can activate relay when switch is in AUTO. |

Use these notes when comparing payload bytes across captures to deduce the encoding for each channel's Hand/Off/Auto state.
